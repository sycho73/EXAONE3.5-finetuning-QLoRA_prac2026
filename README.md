# EXAONE 3.5 7.8B QLoRA 파인튜닝 연습 — 한국어 문장에서 정보 추출 → JSON

무료 Google Colab(T4 GPU) 한 대로 **EXAONE 3.5 7.8B Instruct**를 QLoRA로 파인튜닝한 실습입니다. 한국어 문장에서 인물·장소·기관·날짜·시간·수량을 뽑아 정해진 JSON 형식으로 출력하도록 학습했습니다.

- 노트북: [`exaone_klue_ner_qlora.ipynb`](exaone_klue_ner_qlora.ipynb) (셀 순서대로 실행)
- 학습 15분, 평가 200건 3분 안팎 (무료 T4 기준)

## 결과 요약

학습에 쓰지 않은 평가 데이터 200건으로 튜닝 전후를 같은 조건(같은 프롬프트, greedy 생성)에서 비교했습니다.

| 지표 | 튜닝 전 | 튜닝 후 |
|---|---:|---:|
| **F1** (항목·값 쌍 기준) | 0.568 | **0.828** |
| 정밀도 | 0.566 | 0.836 |
| 재현율 | 0.570 | 0.821 |
| 순수 JSON 비율 (앞뒤 설명·코드 블록 없음) | 0.000 | **1.000** |
| 파싱 성공률 | 1.000 | 1.000 |
| 스키마 준수율 (6개 키, 문자열 목록) | 1.000 | 1.000 |
| 원문에 없는 값 비율 (지어낸 값) | 0.022 | **0.008** |

| 항목별 F1 | 튜닝 전 | 튜닝 후 |
|---|---:|---:|
| 인물 | 0.575 | 0.885 |
| 장소 | 0.423 | 0.752 |
| 기관 | 0.585 | 0.711 |
| 날짜 | 0.639 | 0.800 |
| 시간 | 0.435 | 0.813 |
| 수량 | 0.603 | 0.881 |

**해석**

- 원본 모델도 **형식**(파싱·스키마)은 이미 완벽했습니다. 튜닝으로 오른 것은 **내용**입니다. F1이 0.568에서 0.828로 올랐습니다.
- 원본 모델은 200건 모두 JSON을 ` ```json ` 코드 블록으로 감쌌습니다. 튜닝 후에는 지시대로 JSON만 출력합니다.
- 향상의 대부분은 **KLUE 데이터의 표기 기준**을 배운 데서 나왔습니다. 수량은 단위까지만 끊고, 이름은 쪼개고, 그룹 이름도 인물로 봅니다. 파인튜닝은 새 지식보다 이런 형식과 과제 규칙을 가르치는 데 강하다는 점이 그대로 드러났습니다.

**튜닝 전후 출력 예시**

위 지표는 모두 평가 200건 전체로 계산했습니다. 아래는 그중 튜닝 전후 출력이 달라진 첫 사례들을 순서대로 보여 주는 예시입니다. 정답인 것만 고른 것은 아닙니다.

~~~text
문장: 이 놀이기구의 최대 하강각도는 79도이며 최대 주행속도는 시속 105km다.
전  : ```json {"수량": ["79도", "시속 105km"], …} ```
후  : {"수량": ["79도", "105km"], …}                            ← 정답과 일치

문장: 댄스그룹 '터보’ 마이키(조명익·35)가 과거 그룹 해체 후 했던 일을 밝혔다.
전  : ```json {"인물": ["마이키(조명익·35)"], "수량": [], …} ```
후  : {"인물": ["터보", "마이키", "조명익"], "수량": ["35"], …}   ← 정답과 일치
~~~

## 실험 설정

| 항목 | 값 |
|---|---|
| 모델 | [`LGAI-EXAONE/EXAONE-3.5-7.8B-Instruct`](https://huggingface.co/LGAI-EXAONE/EXAONE-3.5-7.8B-Instruct) |
| 방식 | QLoRA: 원본 가중치는 4비트(NF4, double quant)로 고정하고 LoRA 어댑터만 학습 |
| LoRA | r=16, alpha=32, dropout=0.05, 모든 선형층(`all-linear`: q/k/v/out_proj, c_fc_0/1, c_proj) |
| 학습 파라미터 | 약 4,190만 개 (전체 7.8B의 약 0.5%, 설정으로 계산한 값) |
| 학습 | 1 epoch, 실효 배치 16 (4 × 누적 4), 63 step, lr 2e-4 cosine, fp16, paged AdamW 8bit, gradient checkpointing |
| 손실 | 답(completion) 부분에만 손실 적용 (trl SFTTrainer의 prompt/completion 형식) |
| 환경 | Google Colab 무료 T4 (15GB), 4비트 로드 후 GPU 메모리 5.3GB |
| 라이브러리 | transformers 5.x (최신), peft, trl 1.17.1, bitsandbytes |

**학습 loss**

| step | 5 | 10 | 15 | 20 | 25 | 30 | 40 | 50 | 60 |
|---|---|---|---|---|---|---|---|---|---|
| loss | 0.383 | 0.225 | 0.100 | 0.066 | 0.056 | 0.047 | 0.051 | 0.047 | 0.034 |

처음 15 step에 빠르게 떨어진 것은 형식(JSON만 출력)을 먼저 배운 구간으로 보이고, 이후 완만한 구간은 값의 경계와 표기 기준을 다듬는 구간으로 보입니다.

## 데이터

- [KLUE-NER](https://huggingface.co/datasets/klue/klue) (`klue/klue`, `ner` 설정, CC BY-SA 4.0)
- 문장 속 `<경찰:OG>` 같은 태그를 벗겨 입력 문장을 만들고, 태그 값을 모아 정답 JSON을 만들었습니다.
  ```
  입력: 경찰은 또 성매매 알선 자금을 관리한 박씨의 딸(32)과 …
  정답: {"인물": ["박", …], "장소": [], "기관": ["경찰"], "날짜": [], "시간": [], "수량": ["32", …]}
  ```
- 학습 1,000건은 train에서, 평가 200건은 validation에서 뽑아 서로 겹치지 않습니다. 원문 자체에 꺾쇠(`<`, `>`)가 있어 변환이 깨지는 문장은 제외했습니다.

## 평가 방법

정답 JSON과 비교해 코드로 채점합니다. LLM judge는 쓰지 않았습니다.

- **F1 / 정밀도 / 재현율:** 항목과 값의 쌍 집합으로 비교합니다. 파싱에 실패한 출력은 정답을 전부 놓친 것으로 계산합니다.
- **원문에 없는 값 비율:** 모델이 뽑은 값 중 입력 문장에 문자열로 없는 것의 비율입니다. 이 과제에서의 할루시네이션 지표로 썼습니다.

## 실행 중 만난 문제와 해결

노트북에 모두 반영되어 있습니다. EXAONE 3.5는 transformers에 내장되지 않아 모델 저장소의 자체 코드(`trust_remote_code`)로 돌아가서 버전 문제가 많았습니다.

| 증상 | 원인 | 해결 (노트북 위치) |
|---|---|---|
| `create_causal_mask() got an unexpected keyword argument 'input_embeds'` | EXAONE 자체 코드가 transformers 5.1.0 기준 인자 이름(`input_embeds`, `cache_position`)을 씀. 5.2.0부터 바뀜 | 모델을 불러오기 전에 마스크 함수를 감싸 인자 이름을 맞춤 (5번) |
| transformers 5.1.0으로 고정하면 로드 중 CUDA OOM | 5.1.0의 bitsandbytes 4비트 로드 회귀: 압축 전 크기로 GPU에 먼저 올림 | 버전 고정 대신 최신 버전 + 위 패치 사용 (3번) |
| `get_input_embeddings not auto-handled for ExaoneModel` | 최신 transformers가 EXAONE의 임베딩층 이름(`wte`)을 모름 | `model.transformer._input_embed_layer = "wte"` (5번) |
| 메모리 7.0GB 사용 | EXAONE 설정의 기본 dtype이 float32라 임베딩과 출력층이 float32로 올라감 | `dtype=torch.float16` 지정 → 5.3GB (5번) |
| `"_amp_foreach_non_finite_check_and_unscale_cuda" not implemented for 'BFloat16'` | trl 1.17.1이 4비트 모델이면 fp16 설정과 상관없이 LoRA 가중치를 bf16으로 바꿈. T4는 bf16 미지원 | trainer 생성 직후 학습 가중치를 float32로 되돌림 (8번) |

## 한계

- **비교 대상이 하나 빠졌습니다.** "원본 모델 + 예시 몇 개를 넣은 프롬프트(few-shot)"와는 비교하지 않았습니다. 향상의 일부는 프롬프트만으로도 얻을 수 있었을 수 있습니다.
- **평가 200건, 학습 1회**의 결과라 수치에 몇 %p의 흔들림이 있을 수 있습니다. 다만 F1 +0.26은 그보다 훨씬 큰 차이입니다.
- **일반 능력 저하(catastrophic forgetting)는 측정하지 않았습니다.**
- 학습 중 검증 loss는 따로 보지 않았습니다. 과적합 여부는 평가 데이터 성능으로만 판단했습니다.
